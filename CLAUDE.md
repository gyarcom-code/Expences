# Expences

## Структура проекта
- `index.html` — единственный файл. Статический HTML/JS без сборки, без npm, без фреймворков. Весь код (стили + логика) инлайн в одном файле.
- Хостинг: GitHub Pages, репозиторий `gyarcom-code/Expences`, ветка `main` (Deploy from branch, root).
- Публичный URL: https://gyarcom-code.github.io/Expences/

## Описание проекта
Простой статический сайт, который подключается напрямую к Google Sheets через Google Sheets API и показывает аналитику по расходам.

## Источник данных
- Google Sheet ID: `1bfJk8VUQPg-GrMkj2qiXoxcs0RxJPmIBN9ujmXFkXMQ`
- Лист: `Ответы на форму` (результат Google Forms; имя с кириллицей и пробелом — в URL диапазона оборачивается в одинарные кавычки и URL-encode: `'Ответы на форму'!A:D`)
- Доступ: таблица открыта по ссылке на чтение ("Все, у кого есть ссылка")
- API-ключ лежит прямо в `index.html` (переменная `API_KEY`) и коммитится в репозиторий. Это осознанное решение: сайт статический без бэкенда, ключ в любом случае виден в браузере (Network tab) при любом запросе к API — прятать его в отдельный gitignore'нутый файл смысла не имеет, так как тогда он не попадёт на GitHub Pages и сайт сломается. Если нужна реальная защита от злоупотреблений — настраивать ограничения самого ключа в Google Cloud Console (API restrictions → только Sheets API; Website restrictions → только домен GitHub Pages), а не прятать его в git.

## Структура столбцов
- A: Отметка времени (формат `ДД.ММ.ГГГГ ЧЧ:ММ:СС`, источник года)
- B: Категория (строка)
- C: Сумма (число)
- D: Комментарий (строка, может отсутствовать — Google Sheets API обрезает пустые хвостовые ячейки, строка тогда приходит короче 4 элементов)

Между строкой заголовков и данными в листе есть пустая строка — код должен её пропускать (фильтр по `!timestamp || !category`).

## Логика аналитики (реализовано)
1. Загружаются все строки из листа "Ответы на форму" (`A:D`)
2. Год достаётся из "Отметки времени" **ручным regex-парсингом** (`/^(\d{2})\.(\d{2})\.(\d{4})/`), не через `new Date()` — проверено, что `new Date("28.11.2025 18:29:17")` даёт Invalid Date в Safari/JavaScriptCore, хотя в других движках может парситься. Регекс работает одинаково везде.
3. UI — кнопки выбора года (не dropdown)
4. Внутри выбранного года траты группируются по Категории (сумма по каждой)
5. Категории сортируются от самой большой суммы к самой маленькой
6. Bar chart (вертикальный, столбики снизу вверх) в этом порядке: категория → сумма. Подписи категорий под столбцами повёрнуты (45–90°), `autoSkip: false` — видны все категории. Ширина canvas растёт с числом категорий (~70px/категория), обёртка со scroll по X.
7. Ниже графика — таблица записей с Сумма > 8000 за выбранный год: Дата, Категория, Сумма, Комментарий. Обновляется при переключении года. Ячейки рендерятся через `textContent` (не `innerHTML`) — данные из формы Google, которую может заполнить кто угодно, потенциальный XSS иначе.

## Технологии
- Графики: Chart.js v4 (https://www.chartjs.org/docs/latest/), через `<script src="https://cdn.jsdelivr.net/npm/chart.js@4">`, без npm
- Данные: Google Sheets API v4, `GET /v4/spreadsheets/{id}/values/{range}?key={apiKey}`
- Хостинг: GitHub Pages

## Общие правила работы над проектом
- UI максимально простой, без сложного дизайна — фокус на функциональности
- Изменения вносятся в существующую структуру (один файл `index.html`), а не переписыванием с нуля
- Двигаться поэтапно: план/структура → тестовый запрос к API с реальными данными → реализация → как протестировать локально. Показывать результат на каждом шаге перед тем, как переходить к следующему
- Push в git — через GitHub Desktop или сохранённый в macOS Keychain GitHub PAT (fine-grained, права Contents: Read and write на репозиторий); в этой рабочей среде системный `git push` без токена не работает (credential.helper=osxkeychain не имеет креда до первой настройки)
