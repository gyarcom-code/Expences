# Expences

## Структура проекта
- `data.js` — общий модуль, подключается на всех страницах через `<script src="data.js">`. Содержит `SHEET_ID`, `API_KEY`, `SHEET_NAME`, `MONTH_NAMES` (украинские названия месяцев), `formatCurrency()` (сумма с ₴, локаль `uk-UA`, **целое число без копеек** — `Math.round()` + `maximumFractionDigits: 0`), `THEME_COLORS`/`isDarkMode()` (цвета дизайн-системы, см. ниже), `CATEGORY_ICONS`/`getCategoryIconName()`/`categoryIconHTML()` (иконки категорий, см. "Иконки категорий") и `fetchExpenseRows()` — объединяет архив (`history.csv`) и живую Google Таблицу, дедуплицирует, возвращает плоский массив записей `{timestamp, date, day, month, year, category, amount, comment}`.
- `settings.js` — настройки визуальной индикации превышения трат (пороги жёлтый/красный) + функции расчёта среднего и цвета точки. Подключается только на `monthly-trends.html` и `category-trends.html`.
- `inflation.js` — `fetchInflationData()` и `adjustForInflation(amount, year, month, inflationData)`, пересчёт номинальной суммы в цены последнего месяца из `inflation-data.json` ("сколько бы это стоило сегодня"). Подключается только на `monthly-trends.html` и `category-trends.html` (см. "Инфляция" ниже).
- `inflation-data.json` — статический файл с помесячным ИПЦ Украины (2022 — текущий момент), обновляется вручную (см. "Инфляция" ниже).
- `history.csv` — статический архив расходов за закрытые годы (2022-2025), собран один раз из 4 отдельных Google Таблиц прошлых лет. Столбцы: `Timestamp, Category, Amount, Comment`.
- `add-year-to-history.py` — скрипт для ручного пополнения архива, когда очередной год закончится (см. раздел ниже).
- `index.html` — главная страница: фильтры год/месяц, bar chart по категориям, виджет общей суммы, таблица крупных трат.
- `monthly-trends.html` — динамика расходов по месяцам, сравнение нескольких лет, виджет среднего.
- `category-trends.html` — динамика по месяцам в разрезе одной категории, сравнение нескольких лет, виджеты суммы за год и среднего.
- Все HTML-страницы — чистый HTML/JS без сборки, без npm, без фреймворков; стили инлайн в каждом файле (общего CSS-файла нет, страниц пока немного, дублирование минимальное).
- Хостинг: GitHub Pages, репозиторий `gyarcom-code/Expences`, ветка `main` (Deploy from branch, root).
- Публичный URL: https://gyarcom-code.github.io/Expences/ (главная), `/monthly-trends.html`, `/category-trends.html`

## Описание проекта
Простой статический сайт, который показывает аналитику по расходам, объединяя статический архив прошлых лет (`history.csv`) и живую Google Таблицу текущего года. Интерфейс — на украинском языке, с осознанной дизайн-системой (см. ниже), не "дефолтный" вид. Названия категорий унифицированы под список 2026 года (см. "Категории" ниже); комментарии остаются как в исходной таблице (кириллица/русский).

## Дизайн-система
Направление — «Реєстр»: спокойный личный финансовый инструмент, не лендинг. Один акцентный цвет вместо ярких цветных панелей, тонкие hairline-границы вместо теней, моноширинные цифры для сумм.

**Палитра** (CSS-переменные в `:root` каждого HTML-файла, с `@media (prefers-color-scheme: dark)` — тема переключается автоматически системой, отдельного тумблера в UI нет):
| Роль | Light | Dark |
|---|---|---|
| Фон страницы `--page-bg` | `#f4f5f3` | `#14171a` |
| Поверхность карточек `--surface` | `#ffffff` | `#1c2024` |
| Текст основной `--text-primary` | `#12181a` | `#f2f4f3` |
| Текст вторичный `--text-secondary` | `#5b6560` | `#9aa39d` |
| Граница `--border` | `rgba(18,24,26,.10)` | `rgba(255,255,255,.10)` |
| Акцент `--accent` (активные кнопки, ссылки, bar chart, виджеты) | `#0f6e63` | `#3ab6a3` |
| Превышение жёлтый/красный (`settings.js`) | `#fab219` / `#d03b3b` (одинаковые в обеих темах) | |

Категориальные цвета линий (`THEME_COLORS.categorical` в `data.js`, используются в `monthly-trends.html`/`category-trends.html` для разных годов) — фиксированный проверенный порядок хьюев (не переставлять местами при смене фильтра): light `['#2a78d6','#008300','#e87ba4','#eda100','#1baf7a','#eb6834','#4a3aa7','#e34948']`, dark `['#3987e5','#008300','#d55181','#c98500','#199e70','#d95926','#9085e9','#e66767']`. Выбор light/dark набора — через `isDarkMode()` (проверяет `prefers-color-scheme` один раз при рендере графика, не реагирует на смену темы "на лету" без перезагрузки страницы).

**Типографика**: Google Fonts (CDN, без сборки) — **IBM Plex Sans** для интерфейса/заголовков, **IBM Plex Mono** (`font-variant-numeric: tabular-nums`, класс `.mono`) для всех сумм — виджеты, таблица, чипы среднего/суммы за год. Подключается одним `<link>` с несколькими `&family=` в каждом HTML.

**Компоненты**:
- Кнопки (год/месяц/категория): `border-radius: var(--radius-sm)` (8px), прозрачный фон, hairline-граница; активная (`.active`) — залита `--accent`, белый/тёмный текст (`--accent-contrast`); disabled (месяцы без данных) — `opacity:.45`, `cursor:not-allowed`
- Карточки (`.card`): `--surface` фон, hairline-граница, `border-radius: var(--radius)` (12px), без теней
- Чекбоксы годов: нативные `<input type=checkbox>` с `accent-color: var(--accent)`
- Навигация — единая полоска вкладок `.tabs` вверху всех 3 страниц ("Головна · Динаміка · Категорії"), текущая страница подсвечена акцентом снизу
- Иконки категорий — Material Symbols Outlined (тот же Google Fonts CDN), см. "Иконки категорий" ниже

**Адаптивность**: `<meta name="viewport">` на всех страницах; на `max-width: 640px` `#filters-row` схлопывается в одну колонку, таблица крупных трат скроллится по X внутри `.table-wrap`.

## Иконки категорий
`CATEGORY_ICONS` в `data.js` — маппинг название категории → имя иконки Material Symbols Outlined (например, `'Продукты': 'shopping_cart'`). `DEFAULT_CATEGORY_ICON = 'label'` — универсальная иконка для любой категории **вне** этого списка (если в форме появится новая категория, которой нет в маппинге — она получит эту иконку автоматически, ничего чинить не нужно). `categoryIconHTML(category)` возвращает готовый `<span class="material-symbols-outlined">` — используется в кнопках категорий на `category-trends.html` и в колонке "Категорія" таблицы крупных трат на `index.html`. При добавлении новой категории в осознанный список — просто добавить строку в `CATEGORY_ICONS`, не обязательно (иначе получит `label` по умолчанию).

## Структура столбцов (исходные Google Таблицы и history.csv)
- A / Timestamp: Отметка времени (формат `ДД.ММ.ГГГГ ЧЧ:ММ:СС`, источник дня/месяца/года)
- B / Category: Категория (строка)
- C / Amount: Сумма (число)
- D / Comment: Комментарий (строка, может отсутствовать — Google Sheets API обрезает пустые хвостовые ячейки, строка тогда приходит короче 4 элементов)

Между строкой заголовков и данными в живом листе есть пустая строка — код должен её пропускать (фильтр по `!timestamp || !category`).

## Объединение архива и живых данных (data.js)
`fetchExpenseRows()` в `data.js`:
1. Параллельно (`Promise.all`) грузит `history.csv` (через `fetchHistoryRows()`, с собственным CSV-парсером `parseCSV()`, учитывающим кавычки — в архиве есть комментарии с запятыми внутри) и живую таблицу (`fetchLiveRows()`, старое поведение).
2. Дедуплицирует по составному ключу `timestamp|category|amount|comment` (`recordKey()`) — если год оказался в обоих источниках (переходный период), записи не показываются дважды. Это тот же принцип ключа, что и в `add-year-to-history.py`.
3. Возвращает объединённый массив; если `history.csv` недоступен (fetch не ок) — просто возвращает пустой архив и работает только с живыми данными, без падения страницы.

Все 3 HTML-страницы вызывают `fetchExpenseRows()` как один источник правды, не зная о внутреннем разделении на архив/живые данные — это сделано специально, чтобы фильтры (год/месяц/категория) не отличались в зависимости от происхождения строки.

## Пополнение архива новым годом (add-year-to-history.py)
Запускается вручную (обычно в начале следующего года, когда предыдущий закончился) — автоматической проверки "закончился ли год" нет:
```
python3 add-year-to-history.py --dry-run   # посмотреть, что добавится, не трогая файл
python3 add-year-to-history.py             # добавить по-настоящему
```
- Источник по умолчанию — тот же `SHEET_ID`/`SHEET_NAME`, что в `data.js` (текущая живая таблица). Для нового источника (как было в 2022-2025) — передать `--sheet-id`/`--sheet-name` явно.
- Дедупликация — по тому же составному ключу `(Timestamp, Category, Amount, Comment)`, что и в `data.js`. Идемпотентен: повторный запуск с теми же данными добавляет 0 новых строк (проверено практически).
- В конце выводит отчёт: сколько проверено / добавлено / пропущено как дубли.
- Python выбран вместо Node.js, потому что в рабочей среде разработки Node не установлен.
- Скрипт **не переименовывает категории** — если в новом году появятся категории вне текущего списка (см. "Категории" выше), маппинг делать вручную после запуска.

## Логика аналитики

### Главная страница (`index.html`)
1. Данные грузятся один раз при загрузке страницы через `fetchExpenseRows()` (архив + живые, см. выше), дальше все фильтры работают по уже загруженному массиву `allRows` в памяти — повторных запросов нет.
2. Год и месяц достаются из "Отметки времени" **ручным regex-парсингом** (`/^(\d{2})\.(\d{2})\.(\d{4})/`), не через `new Date()` — проверено, что `new Date("28.11.2025 18:29:17")` даёт Invalid Date в Safari/JavaScriptCore, хотя в других движках может парситься. Регекс работает одинаково везде.
3. UI — кнопки выбора года; под ними **сетка месяцев** (`#months`, `display: grid; grid-template-columns: repeat(3, 1fr)`): ряд 1 — кнопка "Всі місяці" на всю ширину (`grid-column: 1 / -1`), ряды 2-5 — все 12 месяцев по 3 в ряд, **рендерятся всегда, независимо от наличия данных**. Месяц, за который в выбранном году нет ни одной записи — `disabled` (серый, некликабельный, пересчитывается заново при каждой смене года через `renderMonthButtons(year)`).
4. Внутри выбранного периода (год, либо год+месяц) траты группируются по Категории (сумма по каждой), сортируются от большей суммы к меньшей.
5. Bar chart (вертикальный, столбики снизу вверх, `backgroundColor` = акцентный цвет темы) в этом порядке: категория → сумма. Подписи категорий под столбцами повёрнуты (45–90°), `autoSkip: false` — видны все категории. Ширина canvas растёт с числом категорий (~70px/категория), обёртка со scroll по X. **Эта диаграмма не использует пороги превышения из `settings.js`** — раскраска только на страницах динамики по месяцам.
6. **Клик по столбику или подписи категории** на графике переходит на `category-trends.html?category=<категория>` с этой категорией уже выбранной (реализовано через `getElementsAtEventForMode(evt, 'index', {intersect:false}, true)` — ловит клик и по бару, и по зоне подписи снизу).
7. Справа от фильтров — колонка из двух карточек (`.widgets-col`), фиксированная вторая колонка CSS Grid (`#filters-row { grid-template-columns: 1fr 220px }`) — **не flex**, специально, чтобы виджеты не "съезжали" при разном числе кнопок месяцев в разных годах:
   - **"Всього за {період}"** — общая сумма всех трат за период (не только >8000), кликабельная, ведёт на `monthly-trends.html?year=<год>`
   - **"Середнє за місяць"** — среднемесячная сумма за выбранный **год** (не зависит от фильтра месяца, считается через `computeMonthlyAverage()` из `settings.js` — тот же принцип, что на страницах динамики), некликабельная, справочная
8. Ниже графика — заголовок "Великі витрати" + строка с полем ввода порога (`#threshold-input`, по умолчанию `8000`) и кнопкой "Застосувати" (`#threshold-apply`, срабатывает и по Enter) — можно менять порог на лету без перезагрузки и без нового запроса к API (`bigAmountThreshold` — `let`, не `const`; повторный рендер идёт по уже отфильтрованному `currentFiltered`). Таблица: Дата, Категория (с иконкой, см. "Иконки категорий"), Сумма, Комментарий. Ячейки рендерятся через `textContent`/`append()` (не `innerHTML` для пользовательских данных) — данные из формы Google, которую может заполнить кто угодно, потенциальный XSS иначе.
9. Суммы везде форматируются через `formatCurrency()` из `data.js` (₴, локаль `uk-UA`, целое число без копеек) — в виджетах, таблице, на оси Y графика и в tooltip.

### Динамика по месяцам (`monthly-trends.html`)
- Чекбоксы годов сверху (можно отметить несколько одновременно). По умолчанию отмечен год из `?year=` в URL (если передан и существует в данных), иначе — последний доступный год.
- Чекбокс "Врахувати параметри інфляції в Україні" (выключен по умолчанию) — управляет **только линиями графика** (и раскраской точек превышения — среднее для порогов пересчитывается в тех же единицах, что показывает график). Не влияет на виджеты — они показывают обе версии всегда, см. ниже.
- Виджеты над графиком — **две строки, обе всегда видны, не зависят от чекбокса**: "Середнє за місяць:" (номінал) и "Середнє за місяць (з урахуванням інфляції):" (в цінах останнього місяця з `inflation-data.json`) — по одному значению на каждый отмеченный год, цветом в тон линии.
- Линейный график: ось X — месяцы (укр. названия из `MONTH_NAMES`), ось Y — сумма по всем категориям за месяц. Один отмеченный год = одна линия, несколько — несколько линий разных цветов (палитра `COLORS` в самом файле).

### Аналитика по категориям (`category-trends.html`)
- Кнопки категорий сверху (одиночный выбор, с иконкой каждой категории — см. "Иконки категорий"), отсортированы по убыванию общей суммы за всё время. По умолчанию выбрана категория из `?category=` в URL (если передана и существует), иначе — категория с наибольшей общей суммой. Активная кнопка определяется по `dataset.category`, не по `textContent` — текст иконки Material Symbols тоже входит в `textContent` (это лигатура шрифта, не картинка), сравнение по нему сломалось бы.
- Чекбоксы годов (та же логика, что на `monthly-trends.html`), по умолчанию — последний год.
- Чекбокс "Врахувати параметри інфляції в Україні" — та же логика, что на `monthly-trends.html` (управляет только графиком, не виджетами).
- Виджеты над графиком — **четыре строки, все всегда видны**: "Сума за рік:" / "Сума за рік (з урахуванням інфляції):" / "Середнє за місяць:" / "Середнє за місяць (з урахуванням інфляції):" — по одному значению на каждый отмеченный год, цветом в тон линии.
- Линейный график: ось X — месяцы, ось Y — сумма **только по выбранной категории**. Несколько отмеченных годов — несколько линий, чтобы сравнить месяц к месяцу между годами.

## Инфляция (inflation.js, inflation-data.json)
Позволяет сравнивать траты за разные годы "в реальных деньгах", а не в номинале, на страницах динамики.

**Формат `inflation-data.json`**: ключ `"YYYY-MM"` → `{ monthlyChangePercent, cumulativeIndex }`. `monthlyChangePercent` — ИПЦ месяц-к-предыдущему-месяцу (100 = без изменений, 101.3 = +1.3%). `cumulativeIndex` — накопленный индекс, база = декабрь 2021 = 100 (уже посчитан заранее, не пересчитывается в рантайме).

**Источник данных**: index.minfin.com.ua (агрегатор с удобными помесячными таблицами) — **сверено с официальными экспресс-выпусками Держстата** (найдены и прочитаны PDF-релизы за январь/февраль/апрель 2026 — цифры совпали дословно, включая накопленный индекс с начала года). Годовые итоги 2022 (126,6%), 2023 (~105,1%), 2024 (~112,0%) при перемножении месячных % тоже совпадают с публично известными официальными годовыми показателями.

**Формула пересчёта** (`adjustForInflation()` в `inflation.js`): `реальна_сума = номінал × (cumulativeIndex[останній_доступний_місяць] / cumulativeIndex[рік-місяць_витрати])`. База — **последний месяц, присутствующий в файле** (не обязательно текущий месяц — если данных за него ещё нет в файле, используется последний доступный). Если для месяца записи нет в `inflation-data.json` (например, слишком новый) — сумма возвращается без изменений (нет искажения, просто "как есть").

**Как обновлять в будущем**: раз в несколько месяцев (или когда понадобится) — зайти на index.minfin.com.ua/economy/index/inflation/, взять новые месячные % (в идеале сверить с официальным экспресс-выпуском Держстата — искать на ukrstat.gov.ua/od.ukrstat.gov.ua PDF "ІНДЕКСИ СПОЖИВЧИХ ЦІН", там есть и региональная, и общеукраинская цифра в тексте), досчитать `cumulativeIndex` для новых месяцев (`cumulativeIndex[новый] = cumulativeIndex[предыдущий] * monthlyChangePercent/100`), добавить в JSON. Никакого live-запроса к внешнему API нет и не планируется — файл статичный, как `history.csv`.

**UI**: чекбокс "Врахувати параметри інфляції в Україні" на `monthly-trends.html`/`category-trends.html` управляет **только графиком** (линии + раскраска точек превышения пересчитываются в реальных величинах, когда включён). Виджеты среднего/суммы за год показывают **обе версии одновременно** (номінал + з урахуванням інфляції), независимо от состояния чекбокса — так можно сравнивать, не переключая туда-сюда.

## Пороги превышения трат (settings.js)
Применяется только на `monthly-trends.html` и `category-trends.html` (не на главной странице):
- `CHART_SETTINGS.overageYellowThreshold` (по умолчанию 0%) и `overageRedThreshold` (по умолчанию 20%) — пороги превышения среднемесячных трат, при которых **точка** на линии красится в жёлтый/красный. Пользователь меняет эти два числа в `settings.js` напрямую, без правок остального кода — просто открыть файл, поменять цифры, обновить страницу.
- `computeMonthlyAverage()` — среднее считается **только по месяцам, где есть данные** (сумма > 0), не делится жёстко на 12 — иначе для незавершённого года среднее было бы искусственно занижено.
- `getOveragePointColor()` — красный приоритетнее жёлтого при одновременном выполнении обоих условий. Раскрашивается только точка (`pointBackgroundColor`/`pointBorderColor`), сама линия остаётся в базовом цвете года — так год всё ещё различим при сравнении нескольких лет.
- Если выбрано несколько лет одновременно — среднее и раскраска считаются независимо для каждой линии/года.

## Технологии
- Графики: Chart.js v4 (https://www.chartjs.org/docs/latest/), через `<script src="https://cdn.jsdelivr.net/npm/chart.js@4">`, без npm
- Данные: Google Sheets API v4, `GET /v4/spreadsheets/{id}/values/{range}?key={apiKey}`, плюс статический `history.csv`
- Хостинг: GitHub Pages

## Общие правила работы над проектом
- Дизайн — осознанная минималистичная система (см. "Дизайн-система"), не дефолтный вид, но и без лишней декоративности; фокус на читаемости данных
- Интерфейс — на украинском языке; данные из таблицы (категории, комментарии) — как есть (категории унифицированы под список 2026 года, см. выше), не переводятся автоматически
- Изменения вносятся в существующую структуру, а не переписыванием с нуля; общий код между страницами — в `data.js`/`settings.js`, а не дублируется
- Двигаться поэтапно: план/структура → тестовый запрос к API с реальными данными → реализация по частям → как протестировать локально. Показывать результат на каждом шаге перед тем, как переходить к следующему
- Push в git — через GitHub Desktop или сохранённый в macOS Keychain GitHub PAT (fine-grained, права Contents: Read and write на репозиторий); в этой рабочей среде системный `git push` без токена не работает (credential.helper=osxkeychain не имеет креда до первой настройки)
